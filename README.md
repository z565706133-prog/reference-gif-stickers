# 原创角色动态表情包 Skill

把参考GIF的动作与节奏，转换成你自己的原创角色表情包。

这个 Skill 帮助 Codex 分析参考动作、选择制作路线、整理生成提示词，再完成本地修复、透明背景、中文加字、边缘处理、成品验收和微信投稿素材准备。

**它是一套工作流程与辅助工具，不是安装后自动批量出图的一键软件。**

## 下载与安装

[下载 v4 分享包](https://github.com/z565706133-prog/reference-gif-stickers/blob/main/reference-gif-stickers-v4.zip)

打开链接后，点击 **Download raw file** 下载ZIP，解压得到 `reference-gif-stickers` 文件夹。

将整个文件夹放入：

- Windows：`C:\Users\你的用户名\.codex\skills\`
- macOS / Linux：`~/.codex/skills/`

正确目录应为：

```text
skills/
└── reference-gif-stickers/
    ├── SKILL.md
    ├── 使用说明.md
    ├── agents/
    ├── references/
    ├── scripts/
    ├── licenses/
    └── THIRD_PARTY_NOTICES.md
```

如果安装后没有识别，请重新打开 Codex 或新建对话再试。普通 ChatGPT 对话不一定能加载 Codex Skill，但可以使用包内说明和整理好的提示词手动衔接。

## 使用前准备什么

| 素材 | 是否必需 | 说明 |
|---|---|---|
| 清晰角色图 | 必需 | 一张即可开始，优先正面、无遮挡、无文字 |
| 原始参考GIF | 复刻动作时必需 | 提供GIF文件，不能只用截图代替 |
| 三视图 | 可选 | 转身、侧面、背面动作时有帮助 |
| 表情设定图 | 可选 | 辅助理解角色的情绪变化，不要求逐张制作 |
| 本地字体文件 | 使用指定字体加字时需要 | 请确认具备相应使用权 |
| 旧项目和已通过成品 | 可选 | 用于继续制作，避免从零重建 |

同时说明角色必须保留的特征，例如服装、脸型、眼睛颜色、耳朵、胡须、尾巴和绘画风格。

**三视图、表情设定图都不是开始制作的前提。**现有素材不足时，会先说明需要补什么、用途及是否收费，未经授权不会自动付费补图。授权制作动作，也不自动包含额外的三视图或整套表情设定图。

## 不配置API，可以用吗

**可以。**素材分析和本地处理不需要图片API；生成动作素材时，可以选择窗口生图或API。

| 方式 | 适合情况 | 注意事项 |
|---|---|---|
| 窗口内生成 | 当前窗口提供生图工具，想先试做 | 无需自行填写API密钥；受窗口功能和额度限制 |
| API生成 | 需要指定并验证模型、接口或批次请求 | 需配置密钥、确认模型权限与费用 |

窗口生图不等于无限免费，也不保证能指定任意模型、帧数、尺寸或直接输出GIF。

如果当前窗口没有生图工具，可以先让 Codex 整理提示词，在支持生图的窗口生成，再把原始PNG或GIF带回本地处理。

**v4未内置付费图片生成客户端。**选择API路线后，还需要 Codex 检查当前官方文档，并复用或实现合适的生成客户端。

## API怎样配置

Windows用户可在解压后的 Skill 目录中打开 PowerShell，运行：

```powershell
powershell -NoProfile -File ".\scripts\set_api_key.ps1"
```

在本地隐藏输入完整密钥。脚本会保存到当前Windows用户的 `OPENAI_API_KEY` 环境变量，不写入项目、不显示密钥；此操作会替换已有同名变量。设置后重新打开终端或 Codex。

先运行默认检查：

```powershell
python ".\scripts\check_api.py"
```

这一步不联网，只检查是否存在密钥。

如需检查连通性：

```powershell
python ".\scripts\check_api.py" --check-models
```

这一步只请求官方模型列表，不发送图片生成请求。模型可见不代表图片生成权限、GIF输出或指定参数一定可用。

**不要将密钥发到聊天、写入代码或放进分享包。**详细说明见包内 `references/setup.md`。

## 实际制作流程

### 1. 检查现有项目

先找角色母版、参考GIF、字体、已通过版本和历史参数。已有项目优先继续，不随意重建，也不覆盖原始素材。

### 2. 分析参考GIF

读取帧数、逐帧时长、循环和透明信息，再逐帧观察：

- 关键姿态、手势、视线和表情；
- 道具的位置、形状与运动；
- 文字出现时间、构图和自然遮挡；
- 首尾循环是否衔接。

附带脚本能读取技术信息，但不能自动理解动作、情绪或文字，仍需视觉分析。

### 3. 自动推荐制作路线

Skill会分析并推荐，不需要你逐张选择：

- **关键姿态明确、强调角色一致性**：优先PNG动作帧，再本地合成GIF。
- **连续形变较多**：工具确实支持时，可考虑直接生成动画。

不只按帧数判断。推荐路线会列入批次方案，生成前一起确认；不支持的模型或参数不会静默替换。

### 4. 确认方案与生成额度

生成前展示角色参考、完整提示词、制作路线、请求次数上限和预计费用。

可以一次批准整批，中间本地处理自主完成。请求上限不是必须用完的配额，不会为了抽到更好版本而擅自继续调用。

### 5. 先审核第一张

新角色或新风格先完成一张，确认：

- 外观与画风；
- 动作幅度和节奏；
- 字号、文字位置和白边；
- 深浅背景下的效果。

第一张通过后再扩批，减少整批返工。

### 6. 本地处理与免费修复

按需要去背景、处理边缘、加字和合成GIF。默认保留参考的逐帧节奏；人物统一缩放，避免忽大忽小。

去背景时应区分外部背景与角色、服装及道具内部的浅色细节，保留原有颜色和结构，不能仅按颜色将全部白色或浅色像素设为透明。

审核不过先尝试免费修复。确实需要新增生成请求时，检查是否仍在授权范围；超出范围再确认。

### 7. 验收与对照

重新读取实际导出文件，检查尺寸、体积、帧数、逐帧时长、循环和透明情况，并提供深浅背景预览。

技术检查通过不等于动作自然或角色还原，成品仍需审核。

### 8. 准备微信投稿素材

成品确认后，整理表情GIF、封面、聊天面板图标、详情页横幅和上架文案。

数量、尺寸、文件上限及配套素材要求，按投稿时的微信官方页面核对，不把历史规范当作永久标准。登录、实名及审核仍需按平台流程完成。

## 可以这样开始

**第一次试做：**

> 使用 $reference-gif-stickers。角色图和参考GIF在这些目录……先分析动作、节奏和制作路线，给我第一张方案，不调用付费API。

**使用窗口生成：**

> 这批用窗口生图，不调用API。先整理提示词和第一张方案，我确认后再生成。

**继续已有项目：**

> 使用 $reference-gif-stickers 继续这个项目。保留已通过版本，不覆盖原文件，先检查当前阶段和下一步。

**只做免费修改：**

> 先检查这个GIF的边缘和播放节奏，免费本地修复，另存对照版，不调用图片API。

## 包里有什么、没有什么

包含制作流程、参考资料、离线GIF检查工具、本地密钥设置脚本和只读模型列表检查工具。

不包含API额度、付费生成客户端、角色图片、参考GIF、字体、账号或密钥。

离线GIF检查需要Python和Pillow；API检查脚本只使用Python标准库。用户须自行确认素材和字体的使用权。生成质量、动作复刻和平台过审都不作保证。
